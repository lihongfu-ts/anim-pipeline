# 2D 游戏类型 × 角色动画需求 —— 参考

> 2026-09-09。⚑ 回答一个问题：**这条管线现在是横版定制的，要支持"不同的 2D 游戏"到底差在哪、要改什么、每个角色多少钱。**
> ⚑ 结论先放前面：2D 游戏之间的差别对这条管线只有三件事 —— **角色要几个朝向、镜头俯角多大、要哪些动作**。画风不算（风格框随便换）。

## 二 · 决定难度的三个维度

### 2.1 朝向数（最贵的那个维度）
每多一个朝向 = **多一张立绘**（图生图转身，¥0.05）**+ 每个动作多一发视频**（¥0.40–1.05）。
更麻烦的是一致性叠加：三张不同朝向的立绘要看起来是同一个人，靠的是图像模型的"转身"编辑能力；再往下每个朝向的视频又各自漂一点。

- 侧面：现在这套，最稳。
- 正面（朝观众）：稳。⚠ 薄片武器垂在身侧会变成一条线 —— `WEAPON_POSE` 里"宽面朝向观众"的规矩在这里更要写死。
- 背面：一般稳，但脸看不见 ⇒ VLM 判崩坏少了最重要的线索。
- **斜背面（八方向才有）**：I2V 最容易画崩的朝向 —— 模型会偷偷把人转成正侧面。

### 2.2 镜头俯角
- 0°（侧视）/ 10–20°（卡牌）：稳。
- 30–45°（俯视 RPG / ARPG）：视频模型有把镜头"拉平"回水平视角的倾向 ⇒ 提示词头部要加一句锁镜头（"轻微俯视的 2D 游戏视角，自始至终不变"）。⚠ 这条没实测过，第一次要盯。
- 90°（纯顶视）：不适合 I2V，别试。

### 2.3 动作集
- 循环动作（待机 / 走 / 跑）2s ¥0.40，靠 loop 挑帧，现在已有 VLM 质检。
- 一次性动作（攻击 / 受击 / 死亡）5s ¥1.05（受击 2s ¥0.40），靠 VLM 挑帧。
- 死亡 **⛔ 不能钉尾帧**（首尾同图 = 倒下又站起来），已在 `ACTIONS['die'].last=False`。

## 四 · 管线怎么改：一个 `view` 抽象

⚑ 铁律不变：**⛔ 不重写管线**。每个 (动作, 朝向) 仍然是一条现成的单动作链路。

### 4.1 `VIEWS` 配置表（`web/pipeline.py`）
```
VIEWS = {
  'side': {label:'横版侧视', camera:'', dirs:[('s','侧面','面朝画面左侧')], mirror:{'right':'s'}},
  'card': {label:'放置卡牌', camera:'略微俯视的 3/4 正面视角', dirs:[('f','3/4 正面','面朝画面右下方')], mirror:{}},
  'top4': {label:'俯视四方向', camera:'轻微俯视的 2D 游戏视角，角色全身竖直站立',
           dirs:[('d','正面','面朝画面下方，正对观众'), ('s','侧面','面朝画面左侧'), ('u','背面','背朝观众，面朝画面上方')],
           mirror:{'right':'s'}, base:'s', turn:{d:'把角色转成正面朝向观众…', u:'把角色转成背面…'}},
  'iso8': {… 5 个 dir，base 's'，mirror 3 个 …},
}
```
每个 view 定：立绘的**镜头句**、**朝向列表**（key / 中文 / 面朝句）、**哪个朝向是底图**、**其余朝向的图生图转身指令**、**镜像关系**、**允许的检查项**。

### 4.2 立绘：一张底图 → 其余朝向转身
1. 底图沿用现有流程（生成或上传），默认是侧面（现有模板、现有实测都在这个朝向上）。
2. 其余朝向用 `tools/artgen/edit.py` 图生图：指令 = "把角色转成 X 朝向站立；体型比例、服装、武器、画风、构图大小、灰底完全不变，**只改朝向**"（⚠ 现有"改一版"的后缀写着"朝向不变"，转身要换后缀）。
3. 每张各出一张留白图。
4. 产物：`artifacts.portraits = {s:…, d:…, u:…}`；网页立绘卡显示三张，哪张歪了单独重出那张。

### 4.3 动作：(动作, 朝向) 展开成子动作
- `walk` 在 top4 下展开成 `walk_d / walk_s / walk_u`，label「移动·正面」等；每个子动作 = 现成 `_action()` 一次，源图取该朝向的留白图。
- **运动段只有一份**（审阅卡不变），但措辞要**相对化**：写"面朝方向 / 背后方向"，不写"画面左 / 右"（⚑ 受击、死亡模板现在写的是"画面右侧"，要改）。
- 提示词头部按朝向加一句：`人物{面朝句}，自始至终不转身。` 并在 top4 / iso8 下加镜头句。
- `options[walk]` 的 provider / 秒 / 帧 / 格子对三个子动作共用。

### 4.4 检查按朝向开关
| 检查 | 侧面 | 正面 / 背面 | 斜向 |
|---|---|---|---|
| `_anim_check --facing` 命中帧剪影朝向 | ✅ left | ⛔ 关（没有左右） | ⛔ 关 |
| `_blade_check` 刀变细线 | ✅ | ⛔ 关（侧视专属） | ⛔ 关 |
| `_move_check` 位移 | ✅ | ✅（只是数字） | ✅ |
| VLM 挑帧 / 质检 | ✅ | ✅，**提示里带上朝向**（"角色正对观众，攻击应朝画面下方"） | ✅ |

### 4.5 图集
- 每个朝向仍出自己的单行图集（现有 `vid2anim.py` 不动）。
- `_manifest` 多做一步：同一动作的各朝向**按固定行序**叠成一张 `{action}_dirs.png`（top4 行序 [下, 左, 上]，右 = 引擎镜像左；iso8 行序 [下, 左下, 左, 左上, 上]），manifest 写清 `dirs` / `mirror`。
- 帧数、格子每个朝向必须一样（同一个 options 保证）。

### 4.6 网页
- 「视角」下拉框放在持武器姿势旁边：横版侧视 / 放置卡牌 / 俯视四方向 / 斜 45° 八方向。
- 价格：chip 上 = 动作单价 × 朝向数；立绘按钮 = 底图 + 转身张数；总价照加。
- 结果卡：每个子动作一张 GIF；预览页多一个「四向合图」。

## 五 · 建议的实施顺序

0. **先确认目标游戏到底几个朝向** —— 别看截图猜，进游戏让角色**向上走一步**：朝向不变 = 2 向（侧视角色），现有管线直接出；变成背面 = 4 向或 8 向，再斜着走一步区分。⚑ 2026-09-09 那张 ARPG 截图就是这么被纠正的：看着像八方向，实际上下走不换朝向。
1. **`view` 抽象 + 俯视四方向**（用户已选，⚑ 前提是目标游戏真的会转成背面）。它逼着把"多朝向立绘、方向词相对化、检查开关、图集分行"四件事都做出来。
2. **放置卡牌**：做完 1 之后基本是加一条配置（1 个朝向、换镜头句、关两个侧视检查）。
3. **斜 45° 八方向**：等四方向的**正面 / 背面一致性**验证过再上；先拿一个角色只出"待机 ×5 向"（¥2.0）探斜背面崩不崩，再决定要不要投。

### 第一步的验证方式（别一上来全出）
用现有剑客立绘：
- 转身两张（¥0.10）→ 肉眼看三张是不是同一个人。歪了先调转身指令，不往下走。
- 只出「待机 ×3 向」（¥1.20）→ 看正面 / 背面视频有没有把镜头拉平、武器有没有变线。
- 都过了再出走路 / 攻击。
